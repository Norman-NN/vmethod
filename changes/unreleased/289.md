`worker status` now handles a recorded session whose worktree is gone: a 404
Location not found on its permission or message read (the session itself still
answers) reports the stopped reason `worktree gone` with the record's stored
tokens and USD instead of aborting. The no-PR listing reads every record on its
own, prints `#n error: <message>` for a failing record, continues and exits
non-zero when any record failed; `mergeStatus`, session closure, wake and
conflict draining, prompt submission and the usage capture/grading guards treat
that condition as a stopped session and fall back to the stored usage.
